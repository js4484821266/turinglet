# Turinglet

AI가 무엇을 말할지보다 언제 말할지를 실험하는 이벤트 기반 AI 대화 프로토타입

## 프로젝트 소개

Turinglet은 일반적인 질문-답변형 챗봇이 아니라, 대화의 타이밍을 제어하는 실험 프로젝트입니다.

핵심 문제 정의는 단순합니다.

- 사용자가 말한 직후 항상 바로 답하는 방식이 실제 대화 흐름과 맞지 않는 경우가 많다.
- 침묵은 단순 미응답이 아니라 여러 상태일 수 있다.
- 사용자가 입력 중일 때는 답변 생성보다 기다림이 더 자연스러운 선택일 수 있다.

이 프로젝트는 위 문제를 해결하기 위해, 답변 문장 품질 자체보다도 다음 결정을 중심으로 설계했습니다.

- 지금 바로 답할지
- 잠시 기다릴지
- 먼저 짧게 말을 걸지
- 한 번에 몇 개의 메시지를 보낼지

## 기존 턴제 챗봇과 다른 점

- 일반적인 1문 1답 턴제 챗봇이 아닙니다.
- AI가 상황에 따라 먼저 짧게 말을 걸 수 있습니다.
- 사용자 침묵을 단순 미응답으로 처리하지 않고, 여러 가능성으로 해석하려고 시도합니다.
- 사용자가 입력 중이면 끼어들지 않도록 설계했습니다.
- 봇 반응 메시지 수는 고정되지 않습니다.
- 봇이 보내는 반응 메시지 개수는 상황에 따라 0개, 1개, 여러 개가 될 수 있습니다.

## 주요 기능

- 실시간 채팅 인터페이스
- 사용자 입력 중 상태 감지 및 반영
- 대화 상태를 기반으로 한 반응 타이밍 결정
- 침묵 구간에서의 선제 메시지 시도
- 봇 메시지 배치를 상황별로 다르게 구성
- 로컬 실행 지원
- QR 기반 가입 및 로그인
- 기존 세션 재사용을 통한 대화 이력 복원

## 특징

- 메시지 생성과 메시지 발송 시점을 분리해서 다룹니다.
- 답변 길이보다 대화 흐름의 자연스러움을 우선합니다.
- 사용자가 계속 말을 잇는 구간에서는 봇 개입을 줄입니다.
- 한 번의 반응을 여러 짧은 메시지로 나눠 보내는 전략을 지원합니다.

## 예시 대화 흐름 또는 동작 방식

### 1) 사용자가 계속 입력하는 상황

- 입력 중 상태가 감지되면 봇은 즉시 응답하지 않습니다.
- 사용자가 입력을 멈춘 시점 이후에만 반응 여부를 다시 판단합니다.

### 2) 사용자가 짧게 말하고 멈춘 상황

- 즉시 답변 1개를 보낼 수도 있고,
- 맥락상 기다림이 낫다고 판단하면 메시지를 보내지 않을 수도 있습니다.

### 3) 사용자가 감정적으로 무거운 내용을 남긴 상황

- 짧은 공감 메시지 1개를 먼저 보내고,
- 필요하면 이어지는 질문 메시지를 추가로 보낼 수 있습니다.
- 이때 메시지 수는 고정 2개가 아니라 상황에 따라 유동적입니다.

## 실행 방법

### 1) 설치

  npm install

### 2) 환경 변수 준비

  Copy-Item .env.example .env -Force

아래 항목을 확인합니다.

- LLM_PROVIDER=hf-local
- HF_LOCAL_URL=http://127.0.0.1:8010

### 3) 로컬 LLM 서버 실행

  python -m venv .venv-llm
  .\.venv-llm\Scripts\Activate.ps1
  python -m pip install --upgrade pip
  pip install -r local-llm/requirements.txt
  npm run llm:server

정상 실행 확인

  curl.exe http://127.0.0.1:8010/health

### 4) 앱 실행

  npm run migrate
  npm run dev

기본 주소

- frontend: http://localhost:5173
- backend: http://localhost:4000

## 기술 스택

- Frontend: React, TypeScript, Vite, Zustand, socket.io-client
- Backend: Node.js, Express, Socket.IO, TypeScript, Zod
- Database: SQLite 기본, PostgreSQL 선택
- Local LLM: FastAPI, llama-cpp-python, Hugging Face Hub
- Test: Vitest, Supertest

## 프로젝트 의의 / 한계

### 의의

- 챗봇 성능을 답변 내용 품질만으로 보지 않고, 대화 흐름 제어 문제로 확장해 다뤘습니다.
- 실시간 입력 상태와 침묵 해석을 반응 정책에 연결해, 턴제 한계를 줄이는 방향을 탐색했습니다.

### 한계

- 침묵 해석은 아직 규칙과 휴리스틱 비중이 높아 정교함에 한계가 있습니다.
- 로컬 모델 품질과 속도는 실행 환경 성능에 영향을 크게 받습니다.
- 고위험 정서 상황에 대한 안전 장치는 프로토타입 수준입니다.

## 향후 개선점

- 반응 타이밍 정책을 로그 기반으로 정량 평가
- 침묵 상태 분류 정확도 개선
- 사용자별 대화 스타일 반영 정책 추가
- 개입 빈도와 개입 시점을 자동 튜닝하는 실험
- 운영 환경 기준의 안전 가이드와 대응 흐름 보강
